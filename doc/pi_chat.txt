==============================================================================
pi_chat — Pi agent chat in a vim split

pi_chat spawns the Pi coding agent (`pi --mode rpc`) as a long-lived child
process and chats with it from a dedicated vim window. Your prompts, pi's
streamed replies, tool execution, and pi's own UI requests are rendered into
the transcript in real time. The job is shared: opening the chat while the
agent is running reuses the live conversation.

Requirements: Vim 9.0+ compiled with |+job| and |+channel|, and the `pi` CLI
on $PATH (authenticated beforehand). Neovim is not supported: the plugin is
built on Vim's job/channel API.

==============================================================================
Commands                                                          *pi_chat-commands*

:PiOpen [quiet | <message>]                                   *:PiOpen*
    Open (or focus) the chat window and the thinking panel and start the
    agent. If <message> is given it is sent as the first prompt after
    opening (outer quotes are stripped).

    With `quiet` the chat is opened without stealing focus: no window jump
    and no insert mode on the prompt. Intended for the VimEnter boot hook,
    so that stray startup input can never be silently sent to the agent as
    a message.

:PiSend [<args>]                                              *:PiSend*
    Send a prompt to the running agent from anywhere. While the agent is
    busy the prompt is queued (see |g:pi_chat_streaming_behavior|). With
    no argument, jump to the chat prompt. The agent must already be
    running: otherwise an error asks you to use :PiOpen first.

:PiAbort                                                      *:PiAbort*
    Ask the agent to stop the current run.

:PiClear                                                      *:PiClear*
    Start a fresh conversation by restarting the agent process
    (deliberately not an in-process `new_session`: replacing the session
    invalidates the contexts loaded extensions keep). The context's own
    saved session is deleted from pi's store and the same context-keyed
    session id is reused, so a later :PiOpen resumes the post-clear
    conversation. A folder conversation that the file had only inherited
    (see |pi_chat-resuming|) is left untouched: the file gets its own
    fresh session instead.

:PiRestart                                                  *:PiRestart*
    Re-launch the pi process in place, resuming the same session: the
    transcript, context file and any half-typed prompt are kept. Use it
    after changing |g:pi_chat_args| or pi's own configuration, or to
    recover a wedged agent. It does not reload this plugin's Vimscript.

    The chat's model is chosen on the pi side (e.g. pi's own `/model`);
    the statusline shows the model pi reports.

:PiThinking                                                   *:PiThinking*
    Toggle the read-only thinking panel below the chat (opened
    automatically with :PiOpen). Streams the model's thinking live,
    auto-scrolled to the newest line; height is |g:pi_chat_thinking_height|.
    Thoughts accumulate even while hidden, under a `──── prompt` marker per
    turn, so opening it later shows past thinking; :PiClear / :PiClose wipe
    it.

:PiClose                                                      *:PiClose*
    Close the chat window and stop the agent (tears the session down).

:PiFile [<file>]                                              *:PiFile*
    Point the chat at <file>: the file is injected into future prompts as
    context and its directory becomes the agent's working directory the
    next time the pi process starts (:PiRestart, :PiClear, or reopening a
    parked chat). With no argument, print the current context file.

==============================================================================
Options                                                             *g:pi_chat_*

g:pi_chat_split                                            *g:pi_chat_split*
    Window layout when opening the chat: 'vsplit' (default, on the
    right), 'split' (at the bottom) or 'new' (a horizontal split like
    |:new|; |g:pi_chat_width| is not applied).
    Default: 'vsplit'

g:pi_chat_width                                          *g:pi_chat_width*
    Width (vertical split) or height (horizontal) of the chat window.
    An integer is an absolute column/row count; a float between 0 and 1
    is a fraction of the screen (0.4 = 40%), resolved each time the
    chat window is created (re-focusing a visible chat keeps your manual
    resize).
    Default: 60

g:pi_chat_args                                            *g:pi_chat_args*
    Extra arguments appended to the pi command line.
    Default: []

g:pi_chat_no_session                                    *g:pi_chat_no_session*
    Pass --no-session to pi (no persistent session).
    Default: 0

g:pi_chat_streaming_behavior                  *g:pi_chat_streaming_behavior*
    How a prompt is handled while the agent is running: 'followUp' (default)
    queues it until the run fully settles; 'steer' injects it after the
    current tool calls finish.
    Default: 'followUp'

g:pi_chat_show_thinking                            *g:pi_chat_show_thinking*
    Also render thinking deltas inline in the chat as they stream (in
    addition to the :PiThinking panel).
    Default: 0

g:pi_chat_thinking_height                      *g:pi_chat_thinking_height*
    Height of the :PiThinking panel: a float between 0 and 1 is a
    fraction of the screen height (|'lines'|); an integer is a row count.
    Default: 0.3

g:pi_chat_markdown                               *g:pi_chat_markdown*
    0 disables the built-in buffer-local markdown highlighting in the
    chat and thinking panels (headings, bold/italic, inline and fenced
    code, lists, quotes and links).
    Default: 1

g:pi_chat_map                                                *g:pi_chat_map*
    Global normal-mode mapping for :PiOpen. Set to '' to disable. It is
    not created when the key already has a normal-mode mapping.
    Default: '<leader>pi'

g:pi_chat_context_file                            *g:pi_chat_context_file*
    Inject the current file's path into prompts as context (and run the agent
    in that directory).
    Default: 1

g:pi_chat_track_files                          *g:pi_chat_track_files*
    When you switch to another file (with :e, :b, ...), update the context
    file and tell pi about it, so its next turn works on the file you are
    looking at. The notice is sent as a regular prompt, so a switch while
    the agent is idle costs one (short) model turn; while pi is busy it
    queues as a follow-up prompt.
    Set to 0 to disable and manage the context file manually with :PiFile.
    Default: 1

g:pi_chat_master_prompt                        *g:pi_chat_master_prompt*
    Standing rules for the whole conversation. A file path (e.g.
    "~/.pi-master-prompt.md") or a plain string of instructions is passed
    to pi with --append-system-prompt, so the rules are in the system
    prompt from the first message of every session (fresh and resumed).
    A readable file is sent as an absolute path and pi loads its
    contents; anything else is treated as inline text. The chat log
    shows which one was applied on a fresh start. Changes take effect
    when the pi job restarts (e.g. :PiClear, or :PiClose + :PiOpen).
    Default: ''

g:pi_chat_autosave_context                      *g:pi_chat_autosave_context*
    When the context file has unsaved changes at send time: 1 saves it
    automatically; 0 (default) asks whether to save your changes first or
    to let pi edit the on-disk version.
    Default: 0

g:pi_chat_run_timeout                          *g:pi_chat_run_timeout*
    A watchdog warning, not a timeout: while a run is in flight, once it
    exceeds N seconds the chat logs "⏱ pi run exceeded Ns - may be stuck"
    and the status line shows "(long run: :PiClose to stop)". The agent
    keeps running; :PiClose force-stops it. 0 disables the warning.
    Default: 300

g:pi_chat_session_resume                      *g:pi_chat_session_resume*
    :PiOpen resumes the pi conversation for the context file (else its
    folder's conversation, else a new one). See |pi_chat-resuming|.
    Default: 1

g:pi_chat_session_fallback_dir              *g:pi_chat_session_fallback_dir*
    When resuming, fall back to the file's folder session if there is no
    file-level session.
    Default: 1

g:pi_chat_session_dir                              *g:pi_chat_session_dir*
    Directory of the pi session store. '' (default) uses pi's own
    (~/.pi/agent/sessions); set it to match a custom pi --session-dir.
    Default: ''

g:pi_chat_resume_max_messages                 *g:pi_chat_resume_max_messages*
    How many prior messages to show at the top of the chat buffer on resume.
    0 shows the whole transcript.
    Default: 50

==============================================================================
Resuming a conversation                                        *pi_chat-resuming*

:PiOpen remembers which conversation belongs to which file. A stable session
id is derived from the context file's path and passed to pi as --session-id,
so opening the same file again resumes that file's conversation; if there is
no file session, the plugin falls back to the folder's conversation (a freshly
opened file inherits its folder's history); otherwise a new conversation
starts. The id is `pchat-<len>-<sha256>` of the resolved path, so every file
gets its own. A resumed transcript is rebuilt from pi's session file: your
prompts appear with the context prefix the plugin injected. On a
resume the prior transcript is shown at the top of the chat buffer, above the
input line. See |g:pi_chat_session_resume|, |g:pi_chat_session_fallback_dir|,
|g:pi_chat_session_dir| and |g:pi_chat_resume_max_messages|. With
|g:pi_chat_no_session| set, no session is used and nothing is resumed.

==============================================================================
Keybindings                                                   *pi_chat-keybindings*

In the chat input line (insert mode):
    <CR>        send the typed prompt
    <C-CR>      insert a newline (build a multi-line prompt)
    <C-c>       abort the current run

    While pi is generating a turn, typing on the input line is ignored
    (any typed text is reverted to the bare prompt). To queue or steer a
    message while the agent is busy, use :PiSend explicitly.

In normal mode, in the chat buffer (buffer-local mappings):
    A           jump to the chat input line and append
    i           jump to the chat input line and start inserting

Extension dialogs: `confirm`, `select` and `input` use Vim's native prompts;
Esc on a `select` list sends a cancellation, never a choice. `editor`
(multi-line text) dialogs are not supported yet and are answered as
cancelled right away, with a notice in the chat.

==============================================================================
Context file & autosave                                       *pi_chat-context*

When a named buffer is open, pi_chat passes its path to the agent and runs the
job in that directory. If the buffer has unsaved changes when you send a
prompt, pi_chat either saves it first (|g:pi_chat_autosave_context| = 1) or
asks you to (default), because pi edits the file on disk.

==============================================================================
Live reload                                                     *pi_chat-reload*

When pi edits or writes your context file via its tools, pi_chat reloads the
buffer from disk so you see the change immediately. If the buffer has your
own unsaved changes, the reload is skipped with a notification and a
`:e!` hint so it never clobbers your work.

==============================================================================
Streaming behavior                                            *pi_chat-streaming*

pi's streamed reply is flushed into the transcript as deltas arrive (drained
by a 50ms timer, so output never interrupts typing). While a run is in progress a status spinner shows activity.
If you send another prompt while the agent is busy, |g:pi_chat_streaming_behavior|
decides whether it is queued (`followUp`) or injected mid-run (`steer`).
